# OPIc 피드백과 학습 흐름 재설계 검토

검토일: 2026-09-11. 대상: 현재 저장소의 결과 화면, 피드백 생성 규칙, 답변·녹음 저장, 반복 연습 동선. 앱 실행 화면이나 실제 학습자 로그를 관찰한 사용성 연구는 아니며, 코드 기반 현황 검토와 공개 연구·공식 서비스 자료를 결합한 제안이다. 제품 코드 변경은 포함하지 않는다.

**추천: 피드백의 완료 지점을 ‘조언을 읽음’에서 ‘새 질문에도 스스로 적용함’으로 옮긴다.** 답변 직후에는 학습 목표 하나와 그 근거를 보여 주고, 같은 화면에서 교정 발화와 재답변으로 이어지게 한다. 모든 지표를 한 번에 보여 주거나 매 답변에 예상 등급을 붙일 필요는 없다.

## 판단의 근거와 한계

이 조사는 공식 평가 기준, 제2언어 구두 교정 피드백, 과제 반복, 분산 연습, 유창성·발음 평가 연구와 서비스 공식 자료를 선별한 검토다. 새로운 체계적 문헌고찰이나 효과크기 재분석은 아니다. 교실 연구의 교사 피드백과 앱의 AI 피드백, 특정 형태 학습과 OPIc 전체 등급 상승은 동일한 결과가 아니다.

**근거가 비교적 일관된 방향:** 교정 후 학습자가 산출하게 하기, 반복 말하기, 분산 연습, 근거를 갖춘 평가, 이해 가능한 말하기를 목표로 삼기.

**검증할 제품 가설:** 첫 화면에 개선점 1개, 선택 확장 2개 이하, 짧은 자기 점검, 힌트→예문 순서, 하단 재답변 버튼, 다음날·일주일 뒤 복습. 이 정확한 조합이 한국 성인 OPIc 학습자에게 최적이라는 직접 비교 연구는 확인하지 못했다.

## 현재 구현에서 확인한 문제

1. **상위 화면에서 활동량이 학습 목표보다 먼저 보인다.** 결과 첫 카드에 답변 수, 전체·평균·고유 단어, 문장 수, 시간, 다시 듣기, 힌트, 녹음 수의 9개 통계가 나온다. ‘문제 다시 뽑기’가 강조 버튼이며 문항 피드백은 접힌 목록 안에 있다. [현재 결과 화면](/Users/ksunho0660/Documents/Yumi-Opic/src/components/ExamResult.tsx:365)
2. **화면과 생성 규칙 모두 공통 답변 틀을 강하게 전제한다.** 총평 뒤 두괄식·디테일·감정을 좋음/보강으로 표시하고, 생성 우선순위는 이야기·연결→디테일→감정→전달→발음→문법으로 고정된다. 자연스러우면 강제하지 말라는 예외 지시는 있지만, 필수 필드와 시각적 순서는 공통 틀을 계속 강조한다. [피드백 화면](/Users/ksunho0660/Documents/Yumi-Opic/src/components/FeedbackDetails.tsx:43), [생성 규칙](/Users/ksunho0660/Documents/Yumi-Opic/src/app/api/feedback/route.ts:115)
3. **역할극 관련 경험을 전화 역할극과 같이 다룬다.** `roleplay_experience`도 전화 요청·문제 전달 기준으로 묶여 있다. 실제 관련 경험 질문은 과거 경험을 서술하는 과제이므로 별도 기준이 필요하다. [유형 구분](/Users/ksunho0660/Documents/Yumi-Opic/src/lib/feedback.ts:8)
4. **읽은 피드백을 실제로 적용했는지 확인하지 않는다.** 최대 5개 조언과 전체 Before/After가 있고 재발화 안내도 있으나, 같은 문항에서 1차·2차 발화를 연결해 목표 개선을 비교하는 흐름은 없다. 현재 재시도는 회차 단위 동선이다. [Before/After](/Users/ksunho0660/Documents/Yumi-Opic/src/components/FeedbackDetails.tsx:165), [재시도 버튼](/Users/ksunho0660/Documents/Yumi-Opic/src/components/ExamResult.tsx:405)
5. **전사 두 개의 차이를 ‘발음 체크’로 연결한다.** 신중한 안내는 있으나 모델이 받는 것은 전사 텍스트다. 이 경로로 특정 소리·강세·억양의 문제를 검증할 수 없다. [분석 경로](/Users/ksunho0660/Documents/Yumi-Opic/src/app/api/feedback/route.ts:132)
6. **녹음이 있어도 전사가 없으면 미답변이다.** 결과 통계뿐 아니라 API도 질문과 전사가 필수다. 먼저 녹음을 전사해 회복할 수 있는 응답까지 배제한다. [입력 검사](/Users/ksunho0660/Documents/Yumi-Opic/src/app/api/feedback/route.ts:180)
7. **복습할 음성이 남지 않는다.** 녹음 URL은 현재 화면에서만 유효하며 저장 기록에는 들어가지 않는다. 별표 조언은 다시 등장하지만, 다음 날짜의 인출 과제나 새로운 주제에서의 적용 이력은 없다. [저장 구조](/Users/ksunho0660/Documents/Yumi-Opic/src/lib/storage.ts:100)

## 평가와 학습 지표 설계

### A. 답변별 진단: 5개 축, 총점 없이

아래 축은 ACTFL FACT를 학습자가 이해하기 쉬운 행동 단위로 풀어 쓴 **제품용 분석 기준**이다. 5개를 동일 가중치로 평균 내지 않는다. 상황·내용의 폭은 한 답변에서 결론내리기 어려우므로 세션별 과제·주제 범위로 별도 관리한다.

| 진단 축 | 판단 질문과 관찰 대상 | 필요한 근거 | 사용자에게 보여 줄 예 |
| --- | --- | --- | --- |
| 질문 수행 | 질문에 실제로 답했나? 요구한 묘사·비교·질문·대안 제시를 수행했나? | 질문 원문 + 확인된 전사; 세부 요구가 있을 때 충족 여부 | ‘문제 설명은 됐고, 두 번째 대안이 남았어요.’ |
| 내용 연결·전개 | 문장들이 하나의 설명이나 경험으로 이어지나? 시간·원인·대조·결과 관계가 드러나나? | 전사 구간 + 질문 유형 | ‘행동까지 들리지만 그 뒤 결과를 알기 어려워요.’ |
| 언어 조절 | 시간 관계, 지시 대상, 어휘 선택을 안정적으로 조절하나? 막힐 때 풀어 말할 수 있나? | 확인된 전사; 반복되는 패턴과 실제 사용 기회 | ‘지난 일을 말하는 핵심 동사들이 현재형으로 반복돼요.’ |
| 유창성 | 생각을 전달하다 문장 중간에서 자주 끊기나? 반복·수정 후 말을 회복하나? | 원음 + 타임스탬프; 속도·멈춤·수정의 맥락 | ‘이유를 시작하는 두 구간에서 멈췄어요. 그 구간만 연결해 봐요.’ |
| 이해 용이성·발음 | 청자가 핵심 단어와 메시지를 쉽게 알아들을 수 있나? 강세·분절이 이해를 돕나? | 원음에 근거한 검증된 분석 또는 사람의 청취 | ‘이 단어가 불분명하게 들릴 수 있어요. 해당 구간을 확인해 보세요.’ |

**지금 가능한 것:** 질문 수행·내용 연결·언어 조절에 대한 전사 기반 코칭. 이마저 전사 정확성에 영향을 받는다. 현재 코드의 별도 STT 호출은 음향 분석이 아니므로 유창성·발음 전체 진단의 근거로 충분하지 않다.

**상태:** `충족 / 부분 충족 / 미충족 / 판단 보류`. 질문이 해당 능력을 요구하지 않는 경우 `해당 없음`. 짧은 답변·불명확한 전사·오디오 누락은 실패와 구분한다. 언어 조절처럼 연속적인 축은 UI에서 ‘안정적 / 일부 불안정 / 반복 어려움’으로 풀어 표현할 수 있다.

‘충족’은 **이번 질문의 요구를 충족했다**는 뜻이다. 한 문항의 통과를 해당 숙련도 전체 달성으로 보여 주지 않는다. 재현성은 여러 독립 발화에서 확인한다.

### B. 문항 유형에 맞는 기준

| 유형 | 주요 관찰 기준 | 자동 요구하지 않을 것 |
| --- | --- | --- |
| 묘사 | 무엇을 묘사하는지, 특징과 관계가 구체적으로 연결되는지 | 감정 문장, 사건의 반전, 정해진 첫 문장 |
| 습관 | 무엇을 언제·어떻게 하는지와 관련 설명 | 과거 이야기, 억지 문제 상황 |
| 경험·기억에 남는 경험·역할극 관련 경험 | 사건·시간 관계, 전개, 행동, 질문이 요구한 결과·의미 | 전화 인사, 매번 똑같은 4문단 템플릿 |
| 비교 | 같은 기준에서 양쪽을 비교하고 차이를 설명하는지 | 비교 대상별 특징을 관련 없이 나열 |
| 질문하기 역할극 | 상황에 필요한 질문을 직접 하는지; 수는 질문이 명시할 때만 적용 | 언제나 감정 마무리, AI 상대와의 실제 상호작용 능력까지 평가 |
| 문제 해결 역할극 | 문제·조건 전달, 질문이 요구한 대안·요청의 적절성 | 근거 없는 대안 개수 고정, 낙관적인 결말 강제 |
| 이슈·의견 | 입장, 이유·사례, 질문과의 관련성 | AL 학습자에게 모든 답변의 추상적 가설·논증을 필수화 |

AL 준비에서는 경험을 이어 말하고, 주요 시간대를 다루며, 돌발 상황에 대처하는 능력을 여러 질문에서 확인한다. 모든 답변에 과거·현재·미래를 억지로 다 넣으라는 뜻이 아니다. 단어 개수·감정 문장·연결어 수를 AL의 필요충분조건처럼 쓰지 않는다. [ACTFL 기준](https://www.actfl.org/uploads/files/general/OPIc_Familiarization_Guide.pdf)

### C. 장기 학습 기록

| 지표 | 정의 | 표시 위치 |
| --- | --- | --- |
| 이번 목표 적용 | 같은 질문 재답변에서 선택한 행동이 나타났는지 | 재답변 결과 최상단 |
| 도움 없이 재사용 | 예문·힌트 없이 다른 질문의 첫 답변에서 목표 행동을 수행했는지 | 복습 결과·홈 |
| 며칠 뒤 유지 | 다음날·일주일 뒤 등 정한 검사 시점의 새 질문에서 유지됐는지 | 주간 기록 |
| 반복 오류 패턴 | 해당 표현을 쓸 기회 중 오류가 나타난 경우. 사용하지 않은 답변을 성공으로 세지 않음 | 상세 피드백 |
| 과제 범위 | 묘사·경험·비교·역할극 등에서 독립 발화 근거가 얼마나 있는지 | 모의고사·주간 기록 |
| 연습량 | 실제 말하기·재답변·복습 횟수; 기술 실패와 구분 | 활동 기록 |

분모를 함께 보여 준다. 예: ‘새 질문 3개 중 2개에서 결과까지 말함’. 표본이 적을 때 비율이나 성장 그래프를 과장하지 않는다. 같은 질문의 외운 재답변과 새 질문의 독립 답변을 섞어 평균 내지 않는다.

### D. 등급 추정

현재 단계에서는 답변별 예상 등급과 100점 총점 도입을 권하지 않는다. 원하면 ‘등급 참고’는 모의고사 결과의 접힌 영역에 두되, 실제 도입 전 다양한 주제·기능의 **오디오 첫 답변**으로 사람 평가와 비교해야 한다. 사용자별·문항별로 분리한 검증 자료, 한국어 모어 학습자·기기·레벨별 편향, 반복 채점 안정성, 인접 등급 혼동, 근거 부족 시 판단 보류를 확인한다. 임의로 ±한 등급 범위를 씌우는 것은 보정된 불확실성 추정이 아니다.

## 답변 후 학습 순서

기본 흐름은 **발화 완료 → 필요 구간만 전사 확인 → 목표 하나 → 근거와 짧은 수정 → 예문 없이 재답변 → 목표 변화 확인 → 새 질문·나중 복습**이다.

1. **답변이 끝나면 먼저 안전하게 남긴다.** 녹음을 확보한 경우 즉시 저장 상태를 보여 준다. 음성이 있는데 전사가 비어 있으면 ‘받아쓰기를 처리 중’ 또는 ‘다시 처리’ 상태다. 미답변으로 단정하지 않는다.
2. **선택적인 짧은 자기 점검을 제공한다.** ‘질문에서 빠뜨린 부분이 있었나요?’ 정도를 분석 대기 중에 보여 준다. 전부 듣기나 전사 교정을 강제하지 않는다. 자가 평가는 정답 채점이 아니다.
3. **핵심 목표 하나를 제안한다.** 실제로 해낸 점 한 문장과 지금 고칠 행동 하나. 선택 로직은 ‘질문 요구 미수행·의미 왜곡 → 반복되는 목표 관련 문제 → 다듬기’이며 증거가 약하면 우선순위를 낮추거나 보류한다. 사용자가 다른 목표를 선택할 수 있다.
4. **그 목표의 근거를 확인한다.** 내 발화의 해당 문장·구간과 ‘왜 청자가 이해하기 어려운지’를 연결한다. 빠진 내용은 없는 인용을 만들지 말고, 요구사항과 답변 끝 등 판단 범위를 밝힌다.
5. **짧게 고쳐 말한다.** 먼저 내용 질문이나 힌트로 한두 문장을 유도한다. ‘막혔어요’를 누르면 뼈대→짧은 예시를 즉시 제공한다. 지식이 없는 학습자에게 추측을 반복시키지 않는다. 문법·발음의 새로운 항목은 필요한 명시적 설명부터 줄 수 있다.
6. **같은 질문에 다시 답한다.** 예문·전사는 숨기고 목표 한 줄만 남긴다. 연습용 권장 길이는 선택적 안내이며 60초 같은 하드 제한을 공통 적용하지 않는다. 전체 응답을 다시 구성해야 국소 교정이 실제 발화에 들어가는지 확인할 수 있다.
7. **선택한 목표의 변화를 먼저 보여 준다.** ‘이번에는 결과까지 말했어요’와 첫 발화·재발화 근거를 짝지어 제시한다. 즉시 새로운 오류 5개를 제시해 완료 지점을 없애지 않는다. 목표가 아직 안 되면 힌트를 바꾸고 짧게 한 번 더 연습하거나 나중 복습으로 넘긴다.
8. **새 질문과 나중 복습으로 이어 간다.** 같은 기능의 다른 질문을 예문 없이 답한다. 다음날·일주일 뒤는 초기 운영 일정 예시이며 실제 성공·실패에 따라 조절한다. 한 번 따라 말한 성공에는 ‘이번 연습에 적용’, 새로운 독립 답변의 성공에는 ‘새 질문에도 적용’이라고 구분한다.

녹음할 수 없는 상황에는 읽기·정리로 마칠 수 있지만 ‘말하기 적용 완료’로 기록하지 않는다. 모든 연습에서 화면 열람과 건너뛰기는 가능하다.

## 화면 UX 제안

### 1. 답변 직후 화면

상단은 ‘해외여행 · 경험 / 첫 답변’, 질문 요약, ‘내용·표현 분석’ 같은 분석 범위로 시작한다. 첫 화면에 긴 질문 원문·통계·전체 답변·모든 진단을 한꺼번에 배치하지 않는다.

- 유지할 강점: ‘어떤 문제가 생겼는지 분명하게 말했어요.’
- 가장 큰 제목: ‘결과를 한 문장으로 마무리해 보세요.’
- 질문과의 연결: ‘질문은 문제가 어떻게 끝났는지도 묻고 있어요.’
- 내 발화 근거: ‘I talked to the hotel staff. It was a bad day.’
- 보조 설명: ‘직원에게 말한 다음 무엇이 달라졌는지는 아직 들리지 않아요.’
- 주 버튼: **이 부분 연습하기**
- 보조 버튼: **바로 다시 답하기**
- 접힌 항목: 질문 원문 / 내 답변 전체 / 다른 피드백 / 학습 기록 상세.

위 문구와 답변은 UX 설명용 가상 예시다. 사용자의 실제 답변 분석이 아니다. 이 예시에서 AI가 ‘직원이 새 방을 줬다’고 사실을 만들어 주지 않는다. 먼저 실제 결과를 사용자에게 묻는다.

### 2. 짧은 교정 화면

‘직원에게 말한 뒤 실제로 어떤 일이 있었나요?’를 보여 주고 한 문장으로 말하게 한다. 막히면 ‘After I talked to the staff, …’처럼 사실을 비워 둔 뼈대를 제공한다. 사용자가 ‘방을 바꿔 줬다’고 말한 뒤에만 ‘They gave me another room.’ 같은 예시를 만들 수 있다.

음성 교정이 목표라면 해당 구간의 내 음성↔예시 음성을 비교하고 한 가지 소리·강세만 연습한다. 전체 답변 쉐도잉은 선택 보조 활동이다. 따라서 ‘예문 2~3회 낭독’을 모든 사람의 필수 완료 조건으로 두지 않는다.

### 3. 재답변 화면

질문과 ‘이번 목표: 마지막에 결과 말하기’를 보여 준다. 원본·AI 수정본은 접힌 상태가 아니라 기본적으로 읽을 수 없는 상태로 시작하고, 도움 버튼을 통해 열 수 있게 한다. 도움을 열면 이 시도는 도움 사용으로 기록한다. 녹음 버튼·진행 상태·마침 버튼이 중심이다. 첫 답변은 덮어쓰지 않는다.

### 4. 변화 확인 화면

상단: ‘이번에는 결과까지 전달했어요.’

아래: ‘첫 답변: 직원에게 말했다 → 재답변: 직원에게 말한 뒤 다른 방을 받았다’처럼 **사용자가 실제로 말한 두 발화**를 비교한다. AI 수정본과 사용자의 재답변을 혼동시키지 않는다. 수치가 유효한 경우에만 보조 표시하고, 목표와 무관한 새 문제는 접힌 상세에 둔다.

주 버튼은 **다른 질문에 적용하기**. 보조 버튼은 **오늘은 마치기**. 끝낸 목표는 복습 목록에 연결하고 다음 방문에 보여 준다. 완료와 평가를 구분하여, 재답변했다는 이유만으로 목표 성공을 확정하지 않는다.

### 5. 홈·모의고사·기록

- **홈:** ‘오늘 다시 말해 볼 것’ 1~3개를 최상단에 제안. 문항 제목보다 기능을 드러낸다. 예: ‘경험의 결과 말하기 · 다른 주제로 1문제’. 기존 주제별·랜덤·모의고사 탐색은 유지한다.
- **일상 연습:** 한 문항 또는 짧은 세트 안에서 코칭 순환을 끝낸다. 매번 14개 문항의 결과 화면을 지나갈 필요가 없게 한다.
- **실전 모의고사:** 시험 도중 코칭·예문 없이 진행. 종료 후 반복되는 과제 미수행이나 언어 패턴을 요약하고 대표 문항부터 고친다. 전체 분석과 리포트는 계속 접근 가능하다.
- **주간 기록:** 문제 수·단어 수보다 ‘도움 없이 새 질문에 적용한 기능’을 우선한다. 분석된 문항·평가하지 못한 문항과 다룬 기능 범위도 보인다.
- **저장 표현:** ‘이 문장을 읽기’에서 ‘이 기능을 새 상황에서 말하기’로 바꾼다. 질문별 저장은 유지하되 기능 태그로 다른 주제에도 연결한다.

### 레이아웃과 상호작용

데스크톱은 읽기 영역 약 680~760px의 한 열을 기본으로 한다. 여러 문항을 검토할 때만 왼쪽에 좁은 문항 목록을 둘 수 있다. 휴대폰은 핵심 목표·근거·주 버튼을 한 열로 배치하고, 전체 Before/After는 위아래로 비교한다. 제품 구현에서는 하단 주 버튼이 콘텐츠·키보드를 가리지 않게 여백과 안전 영역을 확보한다.

핵심 설명은 16px 안팎, 보조 설명은 14px 안팎을 권장한다. 현재 10~11px 라벨을 학습의 핵심 정보에 쓰지 않는다. 터치 버튼은 44px 이상, 키보드 접근과 초점 표시, 색 이외의 ‘충족/보강/보류’ 텍스트를 함께 제공한다. 성공 애니메이션보다 실제로 달라진 발화를 강조한다.

단계적 공개·주 행동 집중은 이 보고서의 설계 판단과 UI 스킬의 일반 원칙을 적용했다. 해당 검색어는 스킬의 세부 데이터베이스에서 일치 항목이 없었으며, 검색 결과가 학습 효과를 검증했다고 해석하지 않는다.

## 분석 실패와 근거 부족 UX

| 상황 | 처리 |
| --- | --- |
| 음성은 있는데 전사가 비었음 | ‘녹음은 저장됐어요. 받아쓰기를 다시 처리해 주세요.’ 재처리 경로 제공 |
| 전사만 있고 오디오 없음 | 내용·표현 코칭 허용. 발음·유창성은 판단 보류, 발음이 나쁘다는 뜻으로 표시하지 않음 |
| 특정 전사 구간이 불확실함 | 해당 구간 듣기·전사 수정. 확인 전에는 그 구간에 기반한 확정 교정을 보류 |
| 사용자가 직접 입력했음 | ‘작성한 답변 코칭’으로 제공. 즉흥 말하기 성취와 분리 |
| 사용자가 전사를 고쳤음 | 실제 발화 복원인지 새 문장 작성인지 구분; 원본과 수정 이력 유지 |
| 녹음이 너무 짧거나 질문에 답하지 못함 | 무조건 낮은 점수를 만들지 않음. 충분히 기록됐는지 확인하고 재답변 권유 |
| 피드백이 실패함 | 저장된 답변을 유지하고 실패한 분석만 재시도. 이미 받은 피드백을 다시 요청하지 않음 |
| 큰 문제가 발견되지 않음 | 개선점을 억지로 생성하지 않고 새 질문에서 재현 확인 |

녹음과 타임스탬프를 갖추지 못한 단계에서는 근거를 텍스트 위치로 표시한다. 없는 오디오 구간 시각을 AI가 생성하게 해서는 안 된다.

## 구현 순서와 필요한 데이터

**우선 1 — 피드백 기준과 첫 동선 교체.** 공통 topic/detail/feeling을 질문별 수행 기준으로 바꾸고, `roleplay_experience`를 경험 서술 기준으로 분리한다. 9개 통계는 상세로 이동한다. 핵심 목표 하나, 근거 구간, 짧은 연습과 문항별 재답변을 연결한다. 전사 불일치는 전사 확인으로 바꾼다. 기존 피드백은 당시 기준으로 받은 기록임을 유지하고 새 기준으로 받은 것처럼 변환하지 않는다.

**우선 2 — 실제 말하기 근거 확보.** 음성만 있는 입력을 처리하고, 오디오와 전사를 분리해 저장한다. 이 앱에서 모바일 녹음이 생략되는 현재 방식은 재검토한다. 한 스트림으로 녹음한 뒤 전사하는 흐름 등을 실제 기기에서 확인하며, 브라우저 실시간 받아쓰기와 동시 녹음이 전제되지 않도록 한다. 녹음 저장·삭제·보관 기간을 사용자가 조절할 수 있게 하고, 현재 브라우저 범위의 저장부터 시작할 수 있다. 타임스탬프는 실제 음성 처리 결과로 확보한다.

**우선 3 — 새 질문과 간격 복습.** 첫 시도·재답변·전이 질문·지연 복습을 연결하고, 기능별 반복 패턴에 맞춰 다음 과제를 제안한다. 홈의 다음 행동을 이 데이터에서 정한다.

**그다음 — 음성 진단과 등급 추정 검증.** 오디오를 받는 것만으로 발음 점수가 타당해지는 것은 아니다. 사람 평가와 비교해 유효성이 확인된 기능부터 추가한다.

필요한 최소 데이터는 다음과 같다.

- 답변: 질문 ID·유형, 시도 ID, 부모 시도 ID, 첫 답변/재답변/새 질문/복습 구분, 도움 사용 여부.
- 근거: 오디오 참조, 전사 원본·확인본, 텍스트 위치 또는 실제 타임스탬프, 분석 가능 영역, 근거 부족 사유.
- 피드백: 질문별 요구, 근거 있는 강점, 목표 ID, 관찰→이유→행동, 힌트·예시, 판단 상태, 평가 기준·모델 버전.
- 학습 결과: 목표 적용 여부, 그 근거, 다음 복습 시점, 새로운 질문에서 독립적으로 수행했는지.

이 연결 정보는 기존 회차 저장만으로는 부족하다. 최소한 ‘원래 답변과 재답변을 함께 보여 주는 기능’에는 시도 간 관계가 필요하다. 첫 답변을 AI 수정본이나 나중 전사로 조용히 바꾸지 않으며, 이전 기준으로 계산한 값을 새 기준과 섞어 성장으로 보이지 않게 한다.

## 효과를 검증하는 방법

첫 검증의 주 결과는 **새 질문의 독립 답변에서 목표 행동이 나타나는가**로 둔다. 답변 분량·체류시간·피드백 열람률은 이를 대신하지 못한다.

1. 소수 사용자로 핵심 목표 이해 여부와 재답변 동선을 먼저 관찰한다. 어느 버튼을 누를지 찾는 데 걸리는 시간, 실제 재발화까지 이어지는지, 전사 오류를 본인 오류로 오해하는지 확인한다.
2. 현재 방식과 제안 방식을 비교할 때 학습 시간·문항 유형·난이도·도움 조건을 가능한 한 맞춘다. 단순 화면 비교와 추가 연습량 효과를 구분한다.
3. 학습 전, 직후, 약 1주 후에 서로 다른 동등 과제의 첫 답변을 수집한다. 동일 질문 재답변의 향상과 새 질문으로의 전이를 별도로 분석한다.
4. 조건을 모르는 평가자가 질문 수행·내용 연결·언어 조절과, 원음이 있으면 이해 용이성을 평가한다. 사람 간 일치도와 AI 판정의 일치도를 확인한다.
5. 재답변 완료율·복습 수행률은 과정 지표, 전사 유래 오교정·이탈·부담은 부작용 지표로 본다. 소수 개인용 앱이면 무리한 유의성 주장 대신 여러 기능에서의 반복 측정과 근거 사례를 축적한다.

‘사용자가 피드백을 많이 읽었다’보다 ‘시간이 지난 뒤 새로운 질문에도 스스로 말할 수 있었다’를 제품의 성공으로 판단한다.
